## 3. 为什么优先逐层版

逐层版相对 ChunkKV 的平均 F1 增量为 +0.01112，21胜/87平/12负；
相对旧 HMO 为 +0.01026，14胜/97平/9负。
HMO-FW 对 ChunkKV 为 +0.00322，11胜/99平/10负。

逐层版目前是更值得投入下一次确认的候选，而不是由于“方法更像旧版本”才优先。

### 方法实际变化

`build_layer_local_hmo_plan` 保留当前 contiguous-CF 的：

- macro-segment 配额；
- Exact / Sparse / Recurrent-only 动作；
- 每段保留 token 数、slack、保护区域和总字节。

只对 Sparse 区域使用各 Full-Attention 层自己的分数选择窗口起点。
各层窗口位置可以不同，但没有改成各层独立分配预算、独立选择 Exact 区域或 per-head 选择。

建议叙事：
**跨区域预算组织与逐层局部放置解耦。区域层决定保留多少与精度，层内决定保留哪里。**

这里的区域是固定 token 切分，不是已经识别的“语义区域”。
不要把当前 contiguous-CF 原型、逐层修订与历史 V6.1 的27B结果混为同一方法版本。
旧共享位置是一项设计限制，不是此前比较不公平或无效。

## 4. 这次结果应怎样解释

四个任务的逐层版对 ChunkKV F1 差值为正，两个为负：

| 任务 | 逐层版 - ChunkKV | HMO-FW - ChunkKV |
|---|---:|---:|
| NarrativeQA | +0.03425 | +0.00978 |
| Qasper | +0.06049 | +0.06710 |
| MultiFieldQA-en | +0.00699 | -0.02094 |
| HotpotQA | +0.01875 | +0.00456 |
| 2WikiMultihopQA | -0.01500 | 0.00000 |
| MuSiQue | -0.03875 | -0.04115 |

不能把506条旧HMO落后与120条逐层版领先直接连成“全面反超”：
这120条中，旧HMO本身已略高于ChunkKV。真正隔离共享位置修补的证据，是同一120条上的逐层版相对旧HMO增量。

逐层版与ChunkKV的总体containment和EM相同，F1领先并不等于多检索出了更多答案。
应检查配对答案的精确性、完整性和长度，保持官方F1为主指标，同时完整记录containment、EM和输出token数。
不同样本的答案命中可能相互抵消；仅凭总体相同也不能断言“全部只是措辞收益”。

HMO-FW保留更多代理分数但生成增益有限，表明当前冻结attention-mass不是任务质量的充分代理。
这不证明扩大可行域有害，也不证明人为macro边界本身具有语义作用。
逐层版与HMO-FW还同时存在窗口宽度、区域配额、Exact和边界约束差异，二者QA差值不能全部归因于coverage。
关于失败样本跨macro边界次数更多的相关性，保留为诊断，不据此加惩罚项或宣布因果结论。

## 5. 与最终候选匹配的理论

设区域 i 的 Sparse 长度 k_i 已固定，a_(l,t) 是第 l 层冻结的token分数。
旧 HMO 在各层使用相同连续窗口 W_i；逐层版选择：

W*_(l,i) = argmax_{W contiguous in S_i, |W|=k_i} sum_{t in W} a_(l,t).

旧窗口在每一层都是合法候选，因此逐层有：

sum_{t in W*_(l,i)} a_(l,t) >= sum_{t in W_i} a_(l,t).

Exact、保护区域和未保留区域不变，故在相同每层字节与区域配额下，逐层版的该代理目标不低于旧共享位置版。
这是条件性、子问题级保证：

- 不证明胜过ChunkKV；
- 不证明最终QA单调改善；
- 不证明coverage配额或Exact选择最优；
- 不等同于HMO-FW的扩大固定chunk可行集保证。

复杂度：若Full-Attention层数为D、上下文长度为T、区域数为n，
逐层窗口选择可按滑动和实现为 O(D*T)，另计全局分配 O(n log n)、位置构造及模型probe/生成。
与HMO-FW的 O(D*T*m) 动态规划不同，不能把DP保证或DP开销写到逐层候选上。

逐层选择在ChunkKV中已存在。HMO的待验证增量是它与区域配额和局部窗口组织的组合，不是“首次逐层选择”。
